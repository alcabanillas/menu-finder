## Purpose

Turns the author's design system tokens, kept in the repo as a versioned snapshot, into the theme the web app uses, so the app follows the design system and cannot silently drift from it.

## ADDED Requirements

### Requirement: Theme generated from the snapshot
The system SHALL generate the app's theme from the design system snapshot (`design-system/tokens.json`) with `pnpm ds:tokens`. The theme SHALL contain one theme variable per colour, radius, shadow and spacing token and one font-size variable per type style, with the type style's line height, letter spacing and font weight when the snapshot gives them. A colour whose value is an alias of another colour (`{ink}`) SHALL refer to that colour's variable, not repeat its value. The generated theme SHALL state that it is generated and the design system version it comes from (`design-system/VERSION`).

#### Scenario: A colour token becomes a colour variable
- **WHEN** the snapshot has the colour token `olive-600` with value `#4d6a0b`
- **THEN** the theme defines `--color-olive-600: #4d6a0b`

#### Scenario: An alias refers to the aliased colour
- **WHEN** the snapshot has the colour token `text-strong` with value `{ink}`
- **THEN** the theme defines `--color-text-strong: var(--color-ink)`

#### Scenario: Radius, shadow and spacing tokens become theme variables
- **WHEN** the snapshot has `radius-pill: 999px`, `shadow-raised: 0 2px 12px -4px rgba(0,0,0,.12)` and `content-max: 440px`
- **THEN** the theme defines `--radius-pill: 999px`, `--shadow-raised: 0 2px 12px -4px rgba(0,0,0,.12)` and `--spacing-content-max: 440px`

#### Scenario: A type style becomes a font size with its properties
- **WHEN** the snapshot has the type style `h1` with font size `34px`, line height `1.1`, weight `800` and letter spacing `-0.02em`
- **THEN** the theme defines `--text-h1: 34px`, `--text-h1--line-height: 1.1`, `--text-h1--font-weight: 800` and `--text-h1--letter-spacing: -0.02em`

#### Scenario: The theme names its origin
- **WHEN** the theme is generated with `design-system/VERSION` holding `1791096508-606b`
- **THEN** the theme starts with a comment saying it is generated by `pnpm ds:tokens`, must not be edited by hand, and comes from design system version `1791096508-606b`

### Requirement: Snapshot validated before generating
The system SHALL reject a snapshot whose tokens do not have the expected shape and SHALL write nothing when it does. A token name SHALL be kebab-case. A value SHALL match the allow-list of its kind: a hex colour or an alias of a colour defined in the snapshot for colours; a length (`0`, or a number with `px`, `rem` or `em`) for radii, spacing, font sizes and letter spacing; a unitless number for line heights; an integer from 100 to 900 for font weights; `none` or a list of lengths with an optional `rgba()`/hex colour for shadows. Sections the generator does not know SHALL be ignored.

#### Scenario: A value that is not a colour is rejected
- **WHEN** a colour token `ink` has the value `red;} body{background:url(https://evil.example)`
- **THEN** `pnpm ds:tokens` fails with an error naming the token `ink`, exits with a non-zero code and leaves the theme file unchanged

#### Scenario: An alias to a colour that does not exist is rejected
- **WHEN** a colour token `text-strong` has the value `{missing}`
- **THEN** generation fails with an error naming the token `text-strong`

#### Scenario: A name that is not kebab-case is rejected
- **WHEN** a radius token is named `pill}`
- **THEN** generation fails with an error naming that token

#### Scenario: A shadow with a url is rejected
- **WHEN** the shadow token `shadow-raised` has the value `0 0 url(https://evil.example)`
- **THEN** generation fails with an error naming the token `shadow-raised`

#### Scenario: An unknown section is ignored
- **WHEN** the snapshot has a section the generator does not know, such as `motion`
- **THEN** generation succeeds and the theme has no variable from that section

### Requirement: Theme and snapshot stay coherent
The committed theme SHALL be exactly what `pnpm ds:tokens` produces from the committed snapshot and version. The test suite SHALL fail when they differ, so neither can be changed alone.

#### Scenario: Committed theme matches the snapshot
- **WHEN** the test suite runs on the committed snapshot, version and theme
- **THEN** generating from the snapshot gives the committed theme byte for byte

#### Scenario: A hand edit of the theme is caught
- **WHEN** the committed theme differs from what the snapshot generates (for example a colour edited by hand)
- **THEN** the coherence test fails and tells to run `pnpm ds:tokens`
