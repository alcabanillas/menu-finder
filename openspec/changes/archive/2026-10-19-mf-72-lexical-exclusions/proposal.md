# Proposal

Implements **MF-72** (`context/roadmap.md`, Sprint 3). Not split into subtasks (author's decision, 2026-10-19).

## Why

A week-wide exclusion ("pollo, sin cerdo") is scored today with the strategy of the search, which is `semantic` by default, as a soft penalty `1 / (1 + n)`. The semantic score cannot tell what a dish contains: it is rescaled per term, so any term "matches" a large part of the catalogue. Measured on 2026-10-19 with `pnpm evals:exclusion-strategies`: "sin caviar", which no dish has, would remove all 36 menus as a filter, and "sin kebab" would keep 3. The raw similarity does not fix it either (`pnpm evals:similarity-floor`: "pastel de carne", absent, 0.705 against "marisco", present, 0.705). The lexical match does tell it for ingredient words (pollo, cerdo, queso, huevo, jamón). The author decided that a week-wide exclusion is a lexical filter (`context/decisiones.md` BUS-superficie-consulta (b), 2026-10-19).

## What Changes

- A week-wide exclusion (an `exclude` constraint in no group) SHALL remove every menu with a dish (of its `slot`, if any) that matches the term lexically, with every strategy and whether or not it is `hard`.
- It no longer counts in the menu score: the `1 / (1 + n)` formula goes, and the menu score is the mean of the other units. A request with only week-wide exclusions gives every kept menu the score 1, so they tie and are ordered by menu number.
- The result reports, for every week-wide exclusion as for every hard unit, how many menus it removes on its own; the search commands print it as a filter, not as a hard constraint.
- An exclusion inside a group is unchanged: semantic, one minus its term score.
- E07 ("vegetariano") is withdrawn from the retrieval golden set: no menu is vegetarian, because none is free of fish, so it cannot tell the strategies apart. It stays in the decomposer golden set.
- `pnpm ingest evaluate-search` is rerun and `evals/search/results.md` and the counts of `context/decisiones.md` EVAL-golden-sets are updated.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `menu-search`: week-wide exclusions become a lexical filter outside the menu score ("Constraint units and menu score", "Hard constraints"); the search commands print every filter ("Search command").

## Impact

- **Code:** `src/application/services/search/find-menus.ts` (lexical scores for week-wide exclusions with every strategy), `src/domain/search/hard-constraints.ts` (they always filter), `src/domain/search/score-menu.ts` (out of the mean), `src/cli/commands/search.ts` (the filter line), and their tests.
- **Data:** read only, as today. One more full-text query per distinct excluded term with the `semantic` strategy; no new call to Gemini. The retrieval golden set (`evals/retrieval/queries.json`, regenerated by `pnpm evals:golden-set`) loses one query: 43 to 42, exclusion 7 to 6.
- **Behaviour users see:** "sin huevo" gives no menu (every menu has egg), "sin caviar" removes none, "sin cerdo" removes the menus whose dishes name pork. **Limitation**, declared in the presentation: no synonyms ("sin cerdo" keeps "Acelgas con jamón") and no categories without a literal ingredient ("gluten", "lactosa").
- **Decisions relied on:** BUS-superficie-consulta (b) (this change implements it), BUS-unidad-plato, EVAL-golden-sets. No decision is contradicted.
- **Security (safety-first P1, SEG-owasp):** the data touched are the menus and recipes (read only) and the request's terms. The new query reuses the lexical match, where a term is never read as query syntax (spec `menu-search`, "Text match of a term"), so A03 Injection stays covered by the existing scenarios. A request can now empty the ranking on purpose ("sin huevo"); that is a valid answer, not an abuse, and the daily limit (SEG-rate-limit) is unchanged. No new endpoint, input or secret.
